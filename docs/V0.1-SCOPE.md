> **Historical document.** v0.1 was an internal milestone and was never
> tagged; its scope shipped as part of the first public release, `v0.2.0`.
> Kept for the reasoning behind the design — see `docs/FOUNDATION.md` and

>

## 1. Definition of "v0.1.0 released"

v0.1.0 is shipped when **all of the following** are true:

- [ ] **Plugin-API shape frozen** in a tagged commit
      (`@framescout/plugin-api@0.1.0`) **before any Detector / Sink / Source
      plugin work begins**. Mid-implementation changes to plugin-api
      require an explicit ARCHITECTURE.md update and a fresh scope review.
- [ ] Repository is **public** on GitHub at
      `github.com/Juice-de-Orange/framescout`.
- [ ] Docker image `ghcr.io/juice-de-orange/framescout:v0.1.0` is
      published, multi-arch (`linux/amd64` + `linux/arm64`),
      cosign-signed, with SBOM (SPDX + CycloneDX).
- [ ] npm packages from §3 are published under the `@framescout` scope.
- [ ] Documentation (§7) is complete and live at
      `juice-de-orange.github.io/framescout`.
- [ ] Show-Reel media file (≤30 s, MP4 or GIF) is committed in
      `docs/media/show-reel.mp4` via **Git LFS** and embedded in
      README. Demonstrates: (1) `framescout init` interactive setup,
      (2) `docker compose up`, (3) one detection arriving in Home
      Assistant via MQTT. (Git LFS is also used for `tests/fixtures/`
      Reolink clips — set up once in Week 1, used by both.)
- [ ] **The seed deployment** (the app Framescout was extracted from) has been migrated to consume the
      published image and has run **at least 7 calendar days** without
      manual intervention. Data flow is identical to pre-migration.
- [ ] CI is green on `main`: lint, typecheck, unit, integration,
      contract, snapshot, plugin-api-shape-snapshot, Bridge-substitution,
      build.
- [ ] Branch protection on `main`: PR review + green CI required.
- [ ] `CHANGELOG.md` is auto-maintained via `release-please`.

**Implementation timeline.** 6-8 weeks of full-time solo work from
Phase 1 (monorepo skeleton + CI scaffolding in week 1) to v0.1.0 tag.
Slip past 10 weeks triggers a scope-reduction review documented in
this file with an explicit list of cut items.

**Week 1 deliverables (gating — no plugin work begins until met).**
- `packages/plugin-api/` package created and tagged
  `@framescout/plugin-api@0.1.0` (translates `ARCHITECTURE.md §5.1-5.3`
  TypeScript interfaces verbatim).
- `.github/workflows/{ci, release, api-snapshot}.yml` green on a stub PR.
- `pnpm-workspace.yaml` resolves; `pnpm install --frozen-lockfile`
  succeeds against a regenerated lockfile.
- `Dockerfile` rewritten without `--ignore-workspace`;
  `docker buildx build --platform linux/amd64,linux/arm64` succeeds.
- **Git LFS configured** for `docs/media/**` and
  `tests/fixtures/reolink-2026-04/**`; `.gitattributes` committed.

## 2. Built-in plugins shipped in v0.1.0

Exactly these built-in plugins ship. Other plugins are post-release (§11).

### Sources
- **`@framescout/source-reolink-hub`** — HTTP-poll a Reolink Hub Mini
  (or Home Hub, Home Hub Pro, RLN-series NVR — same API surface).
  Channels declared in config, mapped to `(deploymentId, cameraId)`.
  Clip download via `cmd=Download`, frames extracted in the decode stage.

### Detectors
- **`@framescout/detector-megadetector-http`** — POST JPEG to a
  MegaDetector HTTP service. MegaDetector v6 compact
  (`MDV6-yolov10-c`) is the recommended target. Returns bounding boxes
  + class + confidence. Built-in `skipFramesWithPersonAbove: 0.15`
  privacy gate; the detector silently returns an empty Detection list
  for frames where a person is detected above threshold.

- **`@framescout/detector-deepfaune-http`** — POST animal-cropped JPEG
  to a DeepFaune V1.3 HTTP service. Apache-2.0 plugin code; **DeepFaune
  model weights are CC BY-NC-SA 4.0 (non-commercial only)**. The plugin
  README displays this prominently and `framescout test pipeline`
  surfaces it. Configured to run after MegaDetector by YAML declaration
  order; consumes MegaDetector's bounding boxes via
  `DetectorInput.previousDetections`. 37 European mammal classes; see
  `docs/data-model.md` for the taxonomy mapping table.

### Sinks
- **`@framescout/sink-http-multipart`** — Generic multipart POST.
  `image` + JSON metadata. Default payload validated against
  `schemas/ingest-v1.json`. Supports a transitional `wireFormat:
  bulletin-v1` config option that emits the legacy `SightingBundle`
  shape (form fields: `cameraSlug`, `capturedAt`, `species`,
  `speciesDe`, `speciesConfidence`, `image`) for compatibility with
  the legacy ingest endpoint during migration. Default
  is `wireFormat: framescout-v1` (the Observation-shaped JSON metadata
  part). The Bridge-substitution test (§6) runs against
  `wireFormat: bulletin-v1` until the legacy receiver upgrades its
  ingest endpoint to the new shape.
- **`@framescout/sink-mqtt`** — JSON message per observation.
  Configurable topic pattern (`{deployment}`/`{camera}` placeholders).
  QoS 0 or 1. Username/password auth.
- **`@framescout/sink-webhook`** — Generic JSON POST. Bearer-token
  auth. Configurable headers.
- **`@framescout/sink-file-ndjson`** — Local NDJSON spool / standalone
  audit log. **Also serves as the on-disk backend for any sink
  configured with `overflow: spool-to-disk`** (see ARCHITECTURE §6.5.1).
  Rotation via top-of-hour or 1000-line whichever-first.

## 4. Core runtime features

- **Pipeline.** Async-iterator chain orchestrated by `@framescout/core`.
- **CPU work.** Piscina pool sized to `availableParallelism() - 1`.
- **Sharpness.** Tenengrad (Sobel-magnitude squared, mean). Laplacian
  remains as toggleable fallback but is no longer default.
- **Composite score.** `sharpness^0.5 × (0.3 + 0.7 × motion) ×
  confidence × edge_penalty` (multiplicative).
- **Adaptive crop** around primary detection with size-aware padding
  and edge-budget redistribution (port from the Bridge `adaptiveCropBox`).
- **Person-skip privacy gate inside Detector plugin** (not in core).
  Configurable threshold per detector (default 0.15).
- **Zero-detection events skipped by default**; per-source
  `emitBlankObservations: true` opt-in for full-fidelity studies.
- **Bounded sink queue.** Per-sink overflow policy (`drop-oldest` |
  `block`; **`spool-to-disk` deferred to v0.2**) and circuit breaker
  (5 failures within 60 s → 30 s open → single-probe half-open).
- **Observability.** pino JSON logs + Prometheus `/metrics` +
  `/healthz` + `/readyz`. (OpenTelemetry tracing on v0.2 roadmap.)
- **Config.** `config.yaml` with `!env`-tag support and `$schema`-aware
  editor UX (Zod-generated JSON Schema).
- **Plugin loader.** Manifest-first; dynamic ESM `import()`;
  Zod-validated config; lifecycle with init-timeout default 30 s.

## 5. CLI (`@framescout/cli`)

```
framescout init                     # interactive scaffold of config.yaml
framescout config validate          # parse + validate config; show resolved view
framescout config schema            # emit JSON Schema for editor support
framescout test sinks               # POST a test frame to every configured sink
framescout test pipeline            # run one fake event end-to-end (see below)
framescout version                  # print versions of core + plugins
# (`framescout sink replay <sinkId>` is v0.2 — depends on spool-to-disk)
```

All commands have machine-readable `--json` output. Exit codes follow the
Unix convention: 0 success, 1 generic pipeline failure, 2 misuse (bad
args), 3 config-validation failure, 4 plugin-load failure.

### `framescout test pipeline` semantics

Reads `config.yaml`, loads all configured plugins, then synthesizes a
`CaptureEvent` referencing a bundled fixture clip
(`@framescout/cli/fixtures/sample-deer.mp4`). The event is run through
the **full pipeline** (decode + score + detect + observe + sink
fan-out). The CLI then asserts the produced `SinkPayload.observation`
conforms to `schemas/ingest-v1.json`. Returns exit 0 on success.

Used in CI as the smoke test for any PR. Also used in `framescout init`
as the final "everything works" verification before the user runs
production traffic.

(`framescout test hub` and `framescout config explain` are on the v0.2
roadmap — see ROADMAP.md.)

## 6. Test coverage

- **Unit tests.** ≥80% line coverage per package; ≥90% on
  `@framescout/plugin-api` and `@framescout/core`.
- **Integration tests.** End-to-end with msw-mocked Detector + Sink.
  One `CaptureEvent` through the full pipeline, asserts on the emitted
  `Observation` shape.
- **Contract tests.** Validate `sink-http-multipart` payload against
  `schemas/ingest-v1.json`. **Any change to `ingest-v1.json` is a
  receiver-breaking change** — CI enforces this via a `grep` on
  `git diff schemas/ingest-v1.json` requiring a major bump label.
- **Snapshot tests.** Byte-for-byte snapshot of the multipart body for
  one reference observation. Diffs surface in PR review.
- **Plugin-api shape snapshot.** `pnpm dlx api-extractor run` produces a
  rolled-up `.d.ts` for `@framescout/plugin-api`. Committed snapshot
  diffed on every PR — any unintended public-API change fails CI.
- **Plugin-loader tests.** Bad manifest, version mismatch, missing
  factory export, schema-validation failure, init timeout, init throw —
  all paths covered.
- **Bridge-substitution test (THE MIGRATION GATE).** CI job builds the
  v0.1.0 image, runs it against checked-in Reolink fixture clips
  (`tests/fixtures/reolink-2026-04/`), and diffs the resulting
  multipart payload against a snapshot from the seed Bridge. Diff =
  test failure. Schema-level diff (key changes) blocks merge; value-
  level diff (timestamps, ULIDs) is normalized before comparison.

**CI matrix (cost-aware):**

- **On every PR**: Node 22 LTS × `linux/amd64` only — single fast build
  (~5 min) on GitHub-hosted Ubuntu runner. Covers lint, typecheck,
  unit, integration, contract, snapshot, plugin-api-shape-snapshot,
  Bridge-substitution. Keeps PR feedback fast.
- **On every push to `main`**: PR matrix above + Node 24 × `linux/amd64`
  build to catch upcoming-Node regressions early. ~10 min total.
- **On release tag (`v*`)**: full 36-job matrix — Node 22 + 24 ×
  `linux/amd64` + `linux/arm64` (via `docker buildx` qemu emulation
  for arm64; ~10× slower but acceptable for occasional releases) × 9
  test categories. Plus multi-arch image build + cosign sign + SBOM +
  npm publish. ~30-60 min total per release.

This trades full per-PR coverage for ~80 % faster iteration. ARM-only
regressions are caught at release time (acceptable for a project
whose primary deployment target is documented to be a Pi 5 running
the released container, not pre-release builds).

## 13. Risk register

Known risks to v0.1.0 delivery + mitigations:

| Risk                                                  | Mitigation                                                |
|-------------------------------------------------------|-----------------------------------------------------------|
| Plugin API drift during build-out forces rework      | Freeze `@framescout/plugin-api` shape in PR #1; tag `plugin-api@0.1.0`; api-extractor snapshot CI gate. |
| Field naming drift (camelCase vs PascalCase)         | ARCHITECTURE §5.3 locks camelCase. CI grep guard for `[A-Z]ID\b` in TS/JSON files (excluding docs/data-model.md, which legitimately mentions both). |
| Observation ↔ Camtrap DP mapping ambiguity           | `docs/data-model.md` contains the full mapping table. The `framescout-sink-camtrap-dp` plugin (v0.4) implements the casing rename in one place. |
| seed-deployment migration finds wire-format gaps             | Bridge-substitution CI test (§6) runs from day one against fixtures. Schema-diff check on both sides. |
| ARM64 onnxruntime-node not needed in v0.1 (HTTP only) | v0.1 has no native binary deps beyond `sharp` (multi-arch supported). ONNX is v0.3. |
| DeepFaune NC weights misunderstood by users           | Plugin README has non-commercial banner; `framescout test pipeline` surfaces it; release notes call it out; **`docs/deepfaune-license-faq.md` (legal-light, plain-English, 1 page) ships with v0.1** explaining what "non-commercial" covers with worked examples plus disclaimer. |
| Reolink firmware quirks break Source                  | Document tested firmware in `docs/sources/reolink-hub.md`; `framescout test sinks` covers the wire-format side. |
| Bus factor (single maintainer)                        | Documentation-first; every design decision lives in ARCHITECTURE.md or docs/. |
| Reolink fixture clips for Bridge-substitution test missing | Generate or anonymize 5-10 representative clips from the seed deployment **before code-freeze**. Commit to `tests/fixtures/reolink-2026-04/` (git-lfs if combined > 100 MB). Without this, the migration gate (§1) cannot run. Estimated effort: ~1 day. |
